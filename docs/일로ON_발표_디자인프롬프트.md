# 일로ON 발표 PPT — Claude Design 디자인 프롬프트

> 이 문서를 Claude Design에 그대로 전달하세요. 슬라이드 내용은 `일로ON_발표_내용.md` 참조.

---

## 0. 한 줄 브리프

일로ON(illo-on) 서비스 발표용 슬라이드 덱을 만들어줘. **웹 제품 UI와 톤을 정확히 맞춰야 한다** — 따뜻한 뉴트럴(베이지·크림) 배경 위에 잉크블랙 텍스트, 절제된 오렌지 액센트, 부드러운 그림자와 큰 라운드. 총 8개 섹션 + 표지 + 마무리. 16:9.

컨셉 키워드: **차분함 · 종이 질감의 웜 뉴트럴 · 에디토리얼 · 여백 · 흐름(flow) 다이어그램 중심**. 절대 아님: 진한 파랑 SaaS 템플릿, 그라데이션 히어로, 네온, 다크 테마, 스톡 일러스트.

---

## 1. 아트 디렉션

- 제품이 "떠 있는 앱 셸"(둥근 24px 카드가 웜 그레이지 바탕 위에 떠 있음) 컨셉이므로, 슬라이드도 **바탕 = `#d6d0c5` 웜 그레이지**, 그 위에 **`#fdfcf9` 오프화이트 패널/카드가 떠 있는** 구조로.
- 모든 카드·패널: 라운드 20px, 1px `#e3ddd0` 보더, 아주 옅은 그림자 (`0 8px 24px rgba(60,48,32,0.06)`).
- 정보는 항상 **카드로 그룹핑**. 맨바닥 텍스트 나열 금지.
- 다이어그램은 이 덱의 주인공. 흐름/파이프라인/관계도를 직접 그린 선-노드 도식으로 (스톡 아이콘 조합 아님). 노드 = 라운드 사각형, 화살표 = 1.5px 잉크 라인.
- 아이콘은 스트로크 스타일(1.5px), 채우기 최소. Lucide/Feather 계열 느낌.
- 사진 사용 안 함. 필요 시 추상 도형 or 제품 UI 목업.

## 3. 타이포그래피

- 서체: **Pretendard** (없으면 Inter / Noto Sans KR / system-ui). 한글·영문 혼용.
- 슬라이드 타이틀: 28~34px, weight 600, 자간 -0.01em, 색 `#1c1a16`.
- 섹션 kicker(작은 라벨): 11px, weight 600, 대문자, 자간 0.04em, 색 `#79705f` — 타이틀 위에.
- 본문: 14~16px, weight 400, 색 `#5d574d`, 행간 1.6.
- 다이어그램 노드 라벨: 13px, weight 500.
- 숫자 스탯: 24~40px, weight 700, 잉크색.
- 코드/enum/API 경로: 등폭 (JetBrains Mono / SF Mono), 13px, `#f0ece3` 배경 칩.

## 4. 레이아웃 시스템

- 16:9, 슬라이드 외곽 여백 최소 64px, 콘텐츠 최대폭 중앙 정렬.
- 상단 러닝 헤더: 왼쪽에 `일로ON` 워드마크(잉크색, weight 700) + 얇은 구분선, 오른쪽에 `01 / 08` 식 섹션 인덱스 (현재 숫자만 오렌지).
- 하단: 없거나 아주 얇은 캡션.
- 격자: 12컬럼 상상, 실제로는 1열 / 2열(6:6, 5:7) / 3열 카드가 주 패턴.
- 표지: 바탕 `#d6d0c5`, 중앙~좌측에 큰 워드마크 + 태그라인 "회의에서 나온 일을, 메신저에서 결정된 일을, 일로ON.", 우측에 앱 셸을 축약한 추상 도식(둥근 레일 + 카드 몇 개).

## 5. 반복 컴포넌트 스펙

- **StatCard**: 오프화이트, 라운드 14px, 큰 숫자 + 아래 캡션 + 좌상단 스트로크 아이콘.
- **Chip / Badge**: 라운드 999px(pill), 파스텔 배경 + 매칭 잉크 텍스트, 12px, 좌우 패딩 10px.
- **StatusBadge**: 앞에 6px 상태색 dot + 라벨.
- **흐름 다이어그램**: 가로 또는 세로, 노드는 라운드 12px 오프화이트 카드, 화살표 1.5px `#5d574d`, 현재/핵심 스텝만 오렌지 보더 2px + `#f3e1cd` 틴트.
- **ERD 표**: 테이블 = 헤더바(잉크 배경 `#201d17` + 흰 텍스트) + 컬럼 리스트(오프화이트), PK/FK는 작은 회색 pill.
- **API 행**: `[METHOD]` 칩(색상: GET 민트 / POST 피치 / PUT 크림 / DELETE 라벤더) + 등폭 경로 + 한 줄 설명.
- **비교(Pain→Solution)**: 좌 Pain 카드(옅은 `#c5433c` 힌트, 살짝 낮은 채도) ↔ 우 Solution 카드(민트 힌트), 사이에 오렌지 화살표.

## 6. 슬라이드별 레이아웃 가이드

| # | 섹션 | 레이아웃 |
|---|---|---|
| 00 | 표지 | 워드마크 + 태그라인 + 우측 앱셸 추상 도식 |
| 01 | 서비스 개요 및 목적 | 상단에 한 줄 정의 카드(전폭) + 하단 3열: 태그라인/타깃, 핵심 워크플로우 가로 흐름 다이어그램(회의·메신저 → AI 분석 → Action Point → 검토 → Task → Sprint → 메인보드) |
| 02 | Pain Point – Solution | 좌우 2열 대응표: 왼쪽 Pain 4개 스택, 오른쪽 Solution 4개 스택, 행마다 오렌지 화살표. 하단에 차별점 배너("AI가 자동 확정하지 않는다: LLM → 구조화된 Action Point → 사용자 검토 → Task") |
| 03 | 시스템 액터 정의 | 3열 액터 카드(팀원 / 관리자 / AI 시스템) 각 카드에 아이콘·역할 1줄·주요 기능 불릿. 하단에 "관리자 = 별도 계정 아님, 프로젝트별 Role" 각주 + (향후) 외부 메신저 흐린 카드 |
| 04 | 요구사항 정리 | 좌측: 구분별 그룹 카드(회원·프로젝트·멤버·업무·Sprint·회의·AI·연계·대시보드) with REQ ID 칩. 우측: MoSCoW 4단(Must/Should/Could/Won't) 미니 리스트. "REQ-01~22 전부 필수 = MVP" 강조 |
| 05 | 서비스 UI 흐름도 (액터별) | 상단: 앱 구조 바(레일 5메뉴 + 헤더 액션). 본문: 3개 스윔레인 — 관리자 flow / 팀원 flow / AI 시스템 파이프라인. 각 레인은 가로 노드 흐름. 9개 화면 목록은 하단 얇은 스트립 |
| 06 | 데이터 모델 설계 | 중앙 ERD 관계도(PROJECT 중심, MEETING·SPRINT·TASK·MEETING_ANALYSIS 위성). 우측 패널: Enum 통일표. 하단: "PROJECT가 묶고 TASK가 MEETING·SPRINT 참조(nullable)" 원칙 배너 |
| 07 | API 명세 정의 | 상단: 도메인별 개수 표(Auth 2 / Project 5 / Member·Invite 3 / Task 6 / Sprint 5 / Meeting 6 / AI 3 / Board 1 = 30). 본문: 핵심 비즈니스 흐름 세로 다이어그램(signup→login→project→invite→join→meeting→analyze→task→sprint). 우측: 인증(JWT Bearer)·에러 규격 카드 |
| 08 | 향후 추가 및 개선사항 | 4개 영역 카드: 기능 확장 / AI 고도화 / 아키텍처(MSA·Gateway·Kafka) / 데이터 모델 진화. 각 카드 3~4 불릿. 오렌지 액센트는 "다음 단계" 1개만 |
| 09 | 마무리 | 표지와 짝 맞춘 클로징: "회의록을 작성하는 데서 끝나지 않고, 결정된 업무가 실제 Task가 되어 Sprint에서 실행되도록 연결한다." |

## 7. Do / Don't

**Do**
- 웜 뉴트럴 바탕을 실제로 칠할 것 (흰색 슬라이드 금지).
- 흐름은 왼→오른 또는 위→아래 일관되게.
- 한 슬라이드 = 한 메시지. 카드 6개 이하.
- 제품에서 쓰는 실제 용어 유지: 메인보드 / 회의 / Action Point / Sprint / Task / 브리핑.

**Don't**
- 파란색·보라색 주조색, 그라데이션 배경, 드롭섀도 과다.
- 3D, 목업 프레임 그림자 남발, 스톡 사진/일러스트.
- 영문 타이틀 강제 (한글 자연스럽게).
- 슬라이드마다 오렌지 떡칠 (액센트는 희소해야 강조됨).
